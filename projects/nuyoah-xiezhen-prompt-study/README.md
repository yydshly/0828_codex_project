> Project 005：研究 `nuyoah-ai-works/nuyoah-xiezhen-prompt` 如何把写真提示词升级为可路由、可执行、可检查、可重做的 Agent 工作流；同时提供六张真实生成样例和一个确定性编译台，分别展示结果能力与规则机制。

## 必要理解（先读这部分）

| 问题 | 结论 |
| --- | --- |
| 它的本质是什么？ | 把摄影师、视觉导演和后期人员可语言化的隐性控制，封装成 Agent 能执行的规则、Prompt 编译流程与质量门禁。 |
| 它控制什么？ | 主题与任务路由、人物身份/摄影风格参考职责、机位与构图、世界空间光照、人物事件、成像质感、系列变量和失败重做。 |
| 它输出什么？ | 结构化写真 Prompt、系列母版或变体、摄影复拍方案和生成后的检查合同。 |
| 它是否提供新的生图能力？ | 不提供。仓库没有模型、LoRA、Face ID、ControlNet 或推理服务，真正生成像素的是外部图片模型。 |
| 它带来的价值是什么？ | 提高表达完整度、系列一致性、可复用性、可检查性和重做可控性，降低团队经验只能靠口传和单次 Prompt 发挥的问题。 |
| 它不能保证什么？ | 不能保证人物跨图一致、跨模型稳定、像素级复刻、真实灯位反推或无人验收的高成功率生产。 |

最短流程可以概括为：

```text
主题 / 任务意图
+ 人物身份与摄影参考
+ 机位、构图、光照、动作与成像控制
→ 写真规则库编译
→ 结构化 Prompt
→ 外部图片模型生成
→ QA、反馈与从原始输入重新编译
```

因此，它比“写真提示词收藏夹”多了任务路由、参考职责、摄影知识和生产合同；但比完整摄影师少了现场观察、人与人沟通、临场审美判断与真实物理执行。

## 一句话结论

它本质仍然是：

```text
用户意图 / 参考图
→ Agent 生成结构化 Prompt
→ 现有图片模型生成图片
```

它没有训练图像模型，没有 LoRA、Face ID、ControlNet、换脸或独立推理引擎。公开发行包的主要资产是 Markdown 规则、JSON 评测用例和一份 Python 合同测试。

真正增加的是中间的**生产控制层**：它规定 Agent 如何判断任务、如何拆参考、如何分配图片职责、如何重建光线、如何编译 Prompt、如何检查输出，以及失败后如何从原始参考重新开始。

因此最准确的定位是：

> **高级提示词工程 + 摄影导演 SOP + Agent 行为合同 + 质量门禁。**

## 原仓库直接提供的能力

### 1. 六种任务路由

1. 详细中文写真 Prompt；
2. 系列母版；
3. 同系列变体关键词链；
4. 网页端抽卡关键词；
5. 单图或组图反向拆解；
6. 更换人物、保留摄影企划的新分镜复拍。

这些模式不是简单改变输出长短，而是改变变量的锁定范围。例如抽卡模式保留风格 DNA、放开动作和场景组合；摄影方案复拍则需要参考职责、分镜、光照拓扑、生成与验收闭环。

### 2. 人物身份与摄影参考分离

- 人物身份图只回答“她是谁”，提供少量稳定五官锚点；
- 写真参考只回答“这套照片怎样被拍出来”；
- 本张事件负责表情、视线、呼吸、嘴角和身体反应；
- 没有身份图时重新生成成年原创人物，不把写真参考人物当成身份来源。

这能减少常见的职责污染：为了保持一张身份图里的脸，连同它的中性表情、妆发、服装和光线一起被冻结。

### 3. 摄影方案复拍

复拍不是逐张换脸，而是先从组图中提取共同写真套餐，再按真实布光事件聚类子方案，为新人物重新设计分镜。

它重点控制：

- 妆发、服装、场景、道具与时代气质；
- 景别、镜头距离、构图语法和人物状态；
- 白平衡、色偏、反差、黑位、高光、锐度、噪点、压缩和景深；
- 主体清晰区、背景大形、次级细节与低细节留白。

### 4. 新机位光照拓扑

工作流把光线表达为：

```text
光源 → 遮挡 / 调制 → 人物落点 → 环境落点与反射 → 曝光结果
```

换机位时，相机可以移动，但窗洞、屋檐、天空和环境反射仍位于原来的世界空间。新的 Prompt 需要重新预测眼神光、面部亮暗、肩臂或道具受光、环境反射和人物与背景曝光关系，而不是让光源跟着镜头旋转。

### 5. 人物事件与背景信息层级

表情不是“自然、灵动、惊喜”等孤立标签，而由可见事件驱动：

```text
现场触发 → 身体即时反射 → 眉眼 / 嘴角变化 → 视线和手部继续追随
```

背景也不是元素越多越好。工作流要求区分主体清晰区、主导大形、次级细节和低细节留白，避免所有枝叶、纹理和高光碎点获得同样的锐度与对比。

### 6. 重做、质量检查与追溯

用户要求重做时，必须回到原始人物图、原始写真参考和本轮反馈，重新编译完整 Prompt。上一轮生成图只用于诊断，默认不作为下一轮视觉输入。

生成结果按写真套餐、布光曝光、色彩、成像质感、人物事件、画面信息层级和原作绝对保真进行检查；未经用户确认不标为最终资产。Eagle 只作为可选归档，不是核心依赖。

## 工作原理

公开包可以看作四层软程序：

| 层 | 公开资产 | 作用 |
| --- | --- | --- |
| 入口路由 | `SKILL.md` | 根据用户语言选择详细、母版、变体、抽卡、拆解或复拍模式 |
| 摄影知识 | `references/prompt-logic.md` | 规定人物、妆造、场景、构图、光线、皮肤反射和输出格式 |
| 执行闭环 | `references/production-reshoot.md` | 规定参考职责、分镜、光照拓扑、生成次数、失败和验收 |
| 回归保护 | `evals/*.json`、`tests/run_contract_tests.py` | 防止触发、边界、署名、重做和便携性规则在版本更新时丢失 |

Agent 在运行时把这些规则读入上下文，然后由通用大模型完成判断和 Prompt 编译；只有当前环境提供图片工具且用户明确要求时，才调用图片生成。

这是一种**上下文编程**，不是参数训练。优势是便于阅读、修改、分发和回归；限制是规则执行质量仍取决于 Agent 和图片模型。

## Project 005 真实样例库

专题页现在包含三套摄影 DNA、每套两个机位或事件变体，共六张真实生成图片：

| 摄影 DNA | 基准图 | 变体图 | 主要观察 |
| --- | --- | --- | --- |
| 雨亭欠曝 | 平视、中近景、落雨触手 | 低机位、湿栏杆前景、整理湿发 | 机位变化后仍保持亭外散射光、屋檐遮挡、人物欠曝与低细节灰绿背景 |
| 奶油柔雾棚拍 | 平视站姿、调整袖口 | 温和俯拍、坐姿、薄纱穿过前景 | 高调但不把白衣、薄纱和肤色压成同一层；大柔光方向仍可读 |
| Y2K CCD 直闪 | 便利店近景、伸手开柜 | 低机位广角全身、开门迈步 | 直闪、偏绿荧光、红眼倾向、软角和轻微数码缺陷组成同一成像机制 |

每张卡片都提供完整生成 Prompt、能力标签、人工 QA、尺寸和文件哈希。机器可读记录位于 [sample-manifest-v1.json](./experiments/sample-library/sample-manifest-v1.json)，原始项目资产位于 [assets/samples](./assets/samples)。

### 样例能证明和不能证明的内容

- 能证明：在这六次实测中，结构化 Prompt 能让风格、光照拓扑、构图、人物事件、背景层级和成像缺陷形成明显且可观察的结果差异；
- 不能证明：跨模型稳定性、重复生成成功率、人物跨图身份一致性，以及上游 Skill 的官方质量；
- 证据边界：全部样例均为 Project 005 使用内置 imagegen 生成的原创成年虚构人物，没有人物身份参考；它们不属于上游仓库，也不是效果指标。

## 交互演示说明

专题页中的“摄影 Prompt 编译台”是我们为研究建立的确定性概念演示，不属于上游仓库；它与前面的真实样例库分开：样例是构建期已经生成并落盘的图片，编译台运行时不会调用 LLM 或图片模型。

它用内置样例展示四类变化：

- 任务模式如何改变输出结构；
- 人物身份图如何改变参考职责；
- 写真参考如何提供摄影 DNA；
- 俯拍或低机位如何触发光照拓扑重新预测。

编译结果用于理解规则；六张生成样例用于观察小样本输出。两者都不代表上游 Skill 的官方生成质量，也不是对任何图片模型的效果承诺。

## 使用场景

### 高匹配

- 为单张写真编写可执行的中文 Prompt；
- 把一套参考组拆成共同视觉 DNA 和分张变量；
- 在保持系列感的同时重新设计动作、视线、构图和道具；
- 更换人物并保留同一摄影企划；
- 为视觉团队建立 Prompt 格式、失败处理和质量检查 SOP；
- 教 Agent 区分身份参考、风格参考和摄影方案参考。

### 条件匹配

- 跨 Midjourney、Flux、即梦等模型复用：需要增加模型适配器和真实回归；
- 大规模批量生产：需要任务队列、成本控制、资产版本和人工抽检；
- 稳定角色系列：需要额外的身份一致性技术，Prompt 规则本身不能保证；
- 商业摄影前期：适合作为企划与沟通草案，不替代摄影师现场判断。

### 不适合直接承担

- 像素级复刻和背景完全不动的换脸；
- 对人物跨图一致性的技术保证；
- 精确反推出摄影师、器材、灯位和后期参数；
- 没有人工验收的全自动生产线；
- 版权、肖像权和商业授权决策。

## 可扩展方向

### P0 · 结构化摄影中间层

把 Agent 的内部摄影方案变成稳定 JSON Schema：人物身份职责、共同写真套餐、布光子方案、分镜、光照预测、成像系统、质量门禁和 lineage 都拥有可验证字段。

### P1 · 多模型编译器

由同一摄影中间层编译 Codex Image、Midjourney、Flux、即梦等目标格式，分别管理参考图数量、尺寸、seed、权重、负面词和模型能力边界。

### P2 · 真实视觉回归

建立获得授权的固定参考组、Prompt、生成结果和人工评分；分别测量企划一致性、身份、光照、色彩、构图、背景层级、人体结构和用户采用率，而不是只检查规则文字存在。

### P3 · 资产与反馈闭环

为每次生成保存输入职责、模型版本、Prompt、参数、结果、失败原因、用户修改和最终采用状态；让重做与版本对比成为可查询的生产记录。

### P4 · 扩大题材与治理

覆盖男性、中老年、双人、家庭、商业肖像和非人物摄影；同时增加肖像授权、参考图来源、商标、输出用途和保留期限等治理字段。

## 对我们的意义

### 值得借鉴的不是“写真词库”，而是 Skill 产品化方法

它展示了如何把个人视觉经验从一段 Prompt 升级为可维护的软件资产：

```text
触发规则
→ 输入职责
→ 领域知识
→ 输出合同
→ 工具授权
→ 失败与重做
→ 质量门禁
→ eval 与版本发行
```

这套结构可以迁移到我们的插画风格、个人 IP、产品视觉、视频分镜和其他生成式资产 Skill。

### 它补充控制层，但不替代模型层

如果底层模型不具备稳定身份、人体、空间或光照能力，再严谨的 Prompt 也只能降低失败概率，不能创造不存在的模型能力。因此采用时应把“规则质量”和“模型能力”分开评估。

### 建议行动

1. 把它作为视觉 Skill 的工程参考和 A/B benchmark，不直接作为我们的底层平台；
2. 复用入口路由、参考职责、重做合同、质量门禁和 eval 结构；
3. 保留我们自己的固定风格配方，不把上游偏年轻女性写真的审美默认扩散到全部视觉任务；
4. 选 3 组获得授权的参考图，用“自由提示词 / 现有 Skill / 结构化摄影中间层”做三组真实回归；
5. 只有回归证明采用率、风格保真或重做成本显著改善，才继续建设多模型和资产闭环。

当前投入建议：**架构参考价值高，直接产品能力中等，底层技术新增为零。**

## 成熟度与边界

- 公开版 `1.1.0` 发布于 2026-08-26，公开历史仍短；
- 公开仓库是从私有真源生成的发行面，不是唯一可编辑真源；
- 合同测试可以通过，但主要检查文件、关键规则和评测用例是否存在；
- 公开包没有真实生成图片、视觉基准数据集或自动视觉评分报告；
- 工作流明确承认结构测试不等于真实生图回归；
- 第一版只正式支持 Codex Image 完整闭环；
- 默认审美和人物基线偏年轻成年女性，扩展到其他人群需要重新设计；
- MIT 许可允许复用与修改，但复制或分发时应保留许可证和版权声明。
