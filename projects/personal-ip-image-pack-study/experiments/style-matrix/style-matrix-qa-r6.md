## 文件级检查

- IP-01 半身贴纸：`1385 × 1136`，`Format32bppArgb`，四角 alpha `0 / 0 / 0 / 0`。
- IP-03 全身贴纸：`1024 × 1536`，`Format32bppArgb`，四角 alpha `0 / 0 / 0 / 0`；外沿存在轻微半透明过渡，登记为 provider 回归样例，不宣称完美抠图。
- IP-06 半身贴纸：`1284 × 1225`，`Format32bppArgb`，四角 alpha `0 / 0 / 0 / 0`。
- 其余四张新增图片为 `Format24bppRgb` 实体背景，未伪装成透明文件。
- 十三张矩阵图片的尺寸与 SHA-256 记录在 `style-matrix-manifest-r6.json`。

## 失败与返工

新增三张贴纸首轮均把棋盘格烘焙进 `Format24bppRgb`。首次背景提取产生真实 alpha；IP-01 和 IP-06 有少量轮廓外残片，IP-03 有轻微半透明外沿。第二次清理的三张结果全部重新烘焙棋盘格；IP-03 的额外重试也仍为不透明 RGB，因此全部拒绝并保留在 `evidence/`。

这组失败揭示两个不同门槛：

1. **技术透明**：文件是否真的拥有 alpha，而不是画了一层棋盘格。
2. **交付透明**：轮廓外是否仍有残片、光晕或半透明污染。

本轮接受 IP-03 的轻微外沿是有记录的研究取舍；产品化版本应加入连通域、alpha 包围盒和边缘污染检测，并在失败时进入可重复的专用抠图 provider，而不是继续随机重绘。

## 能力边界证据

- IP-01 全身、IP-03 换装、IP-04 场景均保留为 BLOCKED 单元；这比生成三张风格不匹配的图更能证明路由价值。
- IP-02 全身保持 CONDITIONAL，因为它超出该风格的首选能力，但本次双脚完整、人物锁可辨。
- IP-06 封面刻意只生成空白标题区，不让图像模型生成不可控伪文字。
