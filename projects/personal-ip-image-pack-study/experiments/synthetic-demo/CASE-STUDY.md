# 真实生成样例：虚构知识博主“林简”

这组图片不是参数化 SVG，也不是上游仓库中的参考图。它们在 2026-08-28 使用 Codex 内置 ImageGen 实际生成，用来验证 `personal-ip-image-pack` 所描述的“角色锚点 → 独立资产 → QA → manifest”流程能否落到真实文件。

人物“林简”为本研究虚构，不对应任何真人。本实验因此能够验证资产生产、身份约束、版本与交付门槛，但不能代替“已授权真人照片的肖像还原一致性测试”。

## 输入约束

- 固定身份：圆脸、黑色中长弧形发型、细圆框眼镜。
- 固定服装：珊瑚红衬衫、海军蓝阔腿裤、奶油色低帮鞋。
- 固定视觉：彩铅编辑插画、纸张肌理、珊瑚 / 海军蓝 / 奶油色。
- 本轮可变：表情、手势、笔记本道具、背景是否透明。
- 每次只生成一个独立文件，不使用九宫格或接触表。

## 发布轨迹

| 版本 | 角色身份 | 本轮变化 | 输出 | QA |
| --- | --- | --- | --- | --- |
| `v1/r1` | 冻结人物原型 | 无 | 透明背景全身锚点 | 通过 |
| `v1/r2` | 继承 `v1` | 微笑、挥手、奶油色纸张背景 | 独立全身资产 | 通过 |
| `v1/r3` | 继承 `v1` | 思考、手持空白笔记本、奶油色纸张背景 | 独立全身资产 | 通过 |
| `v1/r4` | 继承 `v1` | 讲解表情、单手指向、文案留白 | PPT / 课程全身资产 | 通过 |
| `v1/r5` | 继承 `v1` | 庆祝微笑、单手点赞 | 社群反馈全身资产 | 通过 |
| `v1/r6` | 继承 `v1` | 方形头肩构图、海军蓝圆形背景 | 社交头像 | 通过 |

## 真实 QA 发现

第一次生成 `r2/r3` 时虽然提示词要求透明背景，模型却把透明棋盘格画进了 RGB 像素。文件的四角 alpha 均为 `255`，因此被发布门槛拒绝，原始失败样本保存在 `evidence/`。一次背景提取复修仍产生了有色背景，说明“要求透明”不能替代文件级 alpha 检查。

最终决策是把 `r2/r3` 的资产形式改为允许实体背景的 `full_body`，明确登记 `alpha: false`；只有原型锚点登记 `alpha: true`。这正是该库的实际价值：不让一张“看起来像透明”的图混入正式交付。

## 结论

这个样例证明流程可以把真实生成行为组织成可追溯资产，并及时拦截格式幻觉。新增 r4–r6 时没有重新生成或覆盖 r1–r3，说明“可持续扩展”不是口号，而是明确的版本和文件行为。它也暴露了下一步最值得自动化的能力：alpha、尺寸、OCR、角色一致性和文件哈希 QA。

配套文件：

- `character-spec-v1.yaml`：冻结的人物与视觉锁。
- `delivery-manifest-r3.json`：首轮三项资产的历史交付快照。
- `delivery-manifest-r6.json`：六项发布文件、渠道、尺寸、alpha 与 SHA-256。
- `lineage-r6.json`：brief、anchor、各次发布与最终 manifest 的来源关系。
- `acceptance-qa-r6.md`：六项资产的人工与程序化验收记录。
- `generation-prompts.md`：r1–r6 通过资产使用的最终提示词。
