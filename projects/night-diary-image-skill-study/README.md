## 一句话结论

它不是独立图像模型，也不是滤镜算法。它是一份可重复执行的美术指导合同：

```text
原图
→ 提取构图不变量
→ 叠加 Night Diary 风格、文字和可选人物分支
→ 调用宿主图片模型
→ 检查并最多定向重试一次
```

它真正增加的是**图片风格的可发现、可复用、可约束与可验收能力**。结果仍由宿主图像模型生成，因此“构图锁定”和“逐字文字”都是语义约束，不是像素级保证。

## 上游直接提供的能力

### 1. 构图保护型图生图

默认保留：

- 画布比例、裁切、方向和构图；
- 主体数量、身份、位置、姿态、尺度、透视与剪影；
- 地平线、建筑轮廓、窗格、树枝、道路、海岸等关键几何关系；
- 现有招牌、路牌和真实场景文字，除非明确与新增装饰文字冲突。

允许改变色调、光线、胶片颗粒、局部轮廓线和画面文字，不为了增加故事而发明新人物、建筑、车辆、动物、月亮或道具。

### 2. 单一而明确的视觉语言

- 大面积近黑、深蓝、暗褐或靛青负空间；
- 琥珀橙、暖黄、暗红作为局部光源；
- 少量青蓝或蓝紫平衡冷暖；
- 胶片颗粒、轻微软化、克制光晕与旧纸磨损；
- 只沿少量既有窗格、云缘、浪线或建筑轮廓添加不规则白线；
- 情绪安静、孤独、温暖、神秘，避免赛博霓虹与商业海报感。

### 3. 三段式手写独白

用户没有提供文案时，自动生成总计约 12–28 个英文单词：主陈述、括号低声补充和收束句。用户给出文案时逐字使用，不翻译、不改写、不补充。

文字使用粗头记号笔或粉笔感，要求倾斜、连写、抖动、字距与基线不齐，同时仍要逐字可辨。文字放在真实负空间，避开人物面部、关键主体和主要光源。

### 4. 场景适配

公开 `style-guide.md` 为四类场景提供局部规则：

- 城市与住宅窗户；
- 海面、天空与日落；
- 树木与自然剪影；
- 室内、车窗与雨景。

### 5. 人物荧光线条可选分支

只有用户明确提出人物荧光、灯管轮廓或类似要求时才启用。它要求处理所有现有人物，包括边缘裁切人物；锁定数量、位置、姿态、尺度、朝向和遮挡，并避免骨骼图、火柴人、整块白色剪影和新增肢体。

## 工作原理

公开仓库可以看作四层软程序：

| 层 | 公开资产 | 作用 |
| --- | --- | --- |
| 发现与触发 | `SKILL.md` frontmatter、`agents/openai.yaml` | 根据“深夜胶片”“夜窗独白”“人物荧光”等语言自动或显式调用 |
| 执行合同 | `SKILL.md` | 规定输入判断、构图保护、风格、文字、可选分支、工具使用和重试边界 |
| Prompt 模板 | `references/style-guide.md` | 把构图不变量、场景规则、文字和禁止项编译成图片编辑提示 |
| 视觉说明 | `assets/examples/*.png` | 展示目标风格与处理前后案例；当前执行规则没有明确要求把它们自动作为视觉参考输入 |

Agent 运行时读取规则、理解输入图并列出必须保持的元素，然后调用宿主环境的图片编辑能力。仓库中没有：

- 模型、权重、LoRA 或 ControlNet；
- 图像滤镜、分割、OCR 或结构检测代码；
- 批处理、API、GUI 或独立推理服务；
- 自动测试、视觉基准或成功率报告。

因此它属于**上下文编程与提示词工程**，不是参数训练。

## 可复现结构 QA 基线

Project 007 进一步把“肉眼看起来构图保持得不错”拆成四步本地量测：

```text
锁定输入尺寸与 SHA-256
→ 在最长边 640px 的灰度画布提取边缘地标
→ 用固定随机种子的仿射 RANSAC 建立对应共识
→ 对齐后计算约 4.8px 原图容差下的边缘 precision / recall / F1
```

脚本只依赖工作区已有的 Python、NumPy 与 Pillow，不调用 OpenCV、OCR、模型或网络。亮度与饱和度差只描述风格变化，不参与通过判定。

| 接受样本 | 画布锁 | RANSAC 内点 | 内点率 | 容差边缘 F1 | 平均角点漂移 | 平均亮度变化 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 城市旧住宅院落 | `1024×1536` 完全一致 | 85 / 99 | 85.86% | 0.8862 | 0.0833% | −0.2364 |
| 海岸地平线 | `1536×1024` 完全一致 | 43 / 49 | 87.76% | 0.6076 | 0.7407% | −0.4574 |
| 雨夜车窗 · 中文 | `1536×1024` 完全一致 | 43 / 69 | 62.32% | 0.8712 | 0.0223% | −0.0987 |
| 森林站台 · 中文 | `1024×1536` 完全一致 | 14 / 23 | 60.87% | 0.8123 | 0.1849% | −0.1856 |
| 江南水巷 · 中文 | `1254×1254` 完全一致 | 42 / 56 | 75.00% | 0.8817 | 0.0769% | −0.2071 |

当前烟雾阈值为：尺寸完全一致、至少 12 个内点、内点率至少 0.25、容差边缘 F1 至少 0.25、平均角点漂移不超过画布对角线的 2.5%。这是用于发现明显回归的 Project 007 验收线，尚未经过更大测试集校准，不能当作通用质量分数。

从仓库根目录复算：

```powershell
python projects/night-diary-image-skill-study/experiments/run_structure_qa.py
```

运行环境需提供 NumPy 与 Pillow；本次证据由 Codex 工作区的内置 Python 运行时复算。

结构 QA 当前仍不能验证：

- 文案是否逐字、大小写和标点是否正确；
- 人物数量、身份、姿态或面部是否保持；
- 局部区域是否仅发生目标编辑；
- 换模型、换版本或重复运行后的成功率。

## 使用场景

它更接近“已有照片的情绪视觉转译与内容包装”，而不是通用画图或情绪识别。用户提供照片、情绪方向与可选文案；Skill 负责把这些输入编译为稳定的光色、质感、文字、构图保护和验收合同。

| 主要场景 | 适用对象 | 典型输入 | 交付产物 | 核心价值 |
| --- | --- | --- | --- | --- |
| 个人情绪与旅行日记 | 个人创作者、摄影爱好者 | 一张夜景或旅行照 + 当晚一句话 | 情绪日记图、分享卡、回忆封面 | 把私人感受变成可保存、可分享的视觉记录 |
| 音乐、播客与诗性内容包装 | 音乐人、编辑、播客、栏目主理人 | 构图成立的主视觉 + 标题或短独白 | 封面、歌单图、文章头图、诗集配图 | 快速形成统一且有叙事感的内容气质 |
| 日记与心情记录产品 | 日记 App、照片产品、轻量陪伴产品 | 用户照片 + 用户主动选择的情绪 + 用户文案 | 每日视觉卡、月度回顾、私人收藏页 | 增强记录仪式感与留存；不承担心理诊断 |
| 品牌栏目与社交媒体系列 | 品牌内容、城市文化与旅行团队 | 多来源摄影素材 + 固定风格合同 | 系列帖子、栏目封面、活动预热视觉 | 不重构原图也能保持长期视觉一致性 |
| 团队视觉 Skill 工作流 | 视觉 Skill、内容生产与生成式资产团队 | 授权原图 + 构图不变量 + 文案 + 输出用途 | 带 Prompt、版本、QA 与来源的可审计资产 | 把个人审美变成团队可复用、可回归的生产能力 |

### 高匹配

- 城市窗户、旧楼、街道、车窗和雨夜；
- 海岸、天空、树影和大面积负空间；
- 旅行日记、音乐封面、诗集配图、栏目视觉和社交媒体系列；
- 原图构图已经成立，只想改变时间、光色、质感和叙事语气；
- 希望把个人审美沉淀成团队可重复调用的工作流。

### 条件匹配

- 人物较多：需要逐人检查漏描、肢体和遮挡；
- 原图包含重要招牌：需要检查文字是否被模型改写；
- 印刷用途：建议模型只预留文字区，最终使用排版程序叠字；
- 批量生产：需要版本、队列、成本、回归和人工抽检；
- 跨模型使用：需要目标模型适配器和固定测试集。

### 不适合直接承担

- 商品图、建筑测绘、证据或纪实保真；
- 必须像素级保持人脸、文字和局部结构；
- 百分百正确的长文字排版；
- 透明、矢量、分层或可编辑设计源文件；
- 无人工验收的大规模全自动生产。

## 可扩展方向

### P0 · 硬化构图保护

第一步已经完成：五组接受样本具备可复算的尺寸、地标、仿射漂移和容差边缘基线。下一步加入主体分割、人物关键点、深度图和区域蒙版，对主体数量、地平线、遮挡和局部几何漂移做语义级自动检查。

### P1 · 文字后排版

让图片模型负责负空间和手写底纹，最终文案用 SVG、Canvas 或受控手写字库叠加；用 OCR 检查拼写、大小写、标点和额外文字。

### P2 · 模块化与配置化

拆分：

```text
composition-preserving-edit core
├─ night-diary style pack
├─ scene adapters
├─ copy strategy
├─ fluorescent-figure postprocess
└─ visual QA
```

用 YAML/JSON 管理色板、颗粒强度、文字语言、文字位置、人物分支和输出尺寸。

### P3 · 真实视觉回归

建立获得授权的固定参考图、Prompt 和输出集；记录模型版本、OCR、结构漂移、人物数量、人工评分、重试次数和最终采用率。

### P4 · 生产与治理

增加批处理、任务队列、成本、lineage、输出版本、参考图来源、授权范围、商业用途与保留期限。

## 对我们的意义

它在我们现有视觉 Skill 体系中补上一个重要中间层：

```text
固定插画配方：主题 → 新图
构图保护编辑：原图 → 风格化
概念化重构：视觉本质 → 新资产
```

最值得参考的不是 Night Diary 这一个审美，而是以下工程结构：

1. 把审美写成可触发的明确能力；
2. 在风格指令前先声明不可改变的构图合同；
3. 区分默认行为和必须显式开启的特殊分支；
4. 用户文案逐字保留；
5. 生成后检查并限制重试次数；
6. 明确“不增加故事”和“不支持什么”；
7. 把结果保存、展示和回归作为工作流的一部分。

### 建议落地

1. 把它作为图生图 Skill 的架构参考和 A/B 基准，不当成新模型；
2. 抽取共享的 `composition-preserving-edit` 合同，服务我们的多种风格包；
3. 保留 Night Diary 为一个独立可替换配方，不把夜景审美写入全部图片任务；
4. 优先建设 OCR、主体/几何检查、版本追踪和授权字段；
5. 用授权固定图比较“自由提示词 / Night Diary 合同 / 硬结构控制”三种路径的采用率与重做成本。

当前投入建议：**直接风格使用价值中等偏高，视觉 Skill 架构参考价值高，底层技术新增为零，生产化仍需明显工程投入。**

## 成熟度与风险

- 上游公开历史只有 4 次提交，尚无 release；
- Skill 结构校验通过，但没有自动测试与视觉回归；
- 没有脚本和模型，降低了代码执行面，也意味着可靠性完全依赖宿主 Agent 和图片模型；
- 上游示例展示强，但没有 Prompt、模型版本、参数、运行次数和失败样本；
- 当前仓库没有 LICENSE，示例来源与授权链不完整；
- 商业采用前应补许可证、原图授权、输出用途和保留期限。
