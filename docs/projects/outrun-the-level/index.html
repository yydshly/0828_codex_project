01 / RESEARCH QUESTION

这个项目在研究什么？

当玩家只有一个“跳跃”动作时，能否依靠实时生成、持续追赶和重力翻转，形成持续两分钟、可学习、可预判且愿意重玩的完整游戏体验？

研究重点不是增加按钮数量，而是让关卡节奏、视觉提示、物理响应和风险反馈共同制造深度。游戏必须先完成“开始—生存—失败/通关—立即重开—解锁”的闭环，才有资格讨论美术扩展或内容量。

共 6 个约束段落

制作一款完整可玩的 2.5D 横版自动跑酷游戏，名称为“OUTRUN THE LEVEL”。玩家控制一个发光小角色自动向右奔跑。桌面端使用空格或鼠标点击跳跃，移动端点击屏幕跳跃。

核心机制：关卡在玩家前方实时生成，身后的世界被“删除浪”持续吞噬。撞到障碍、掉出跑道或被删除浪追上即失败，并可立即重新开始。

主模式时长为 120 秒。每 20 秒逐渐提高速度和障碍密度，但必须保持公平，不能生成无法通过的组合。加入清晰可预判的重力门，穿过后世界上下翻转，玩家倒挂跑酷，再穿过重力门恢复正常。

完成 120 秒后出现出口，通关并解锁无限模式。记录本局分数、距离、收集物和历史最高分。主界面包含玩法说明和开始按钮，结算页包含再次挑战和无限模式入口。

视觉采用深蓝近黑色的赛博城市。背景保持低亮度、低对比，跑道使用深色实体和细青色边缘。玩家、障碍和危险物必须清晰醒目，减少霓虹雾和 Bloom。不要加入 Ghost、幽灵对手或相关提示。

请制作完整游戏，不是视觉演示。优先保证跳跃响应、碰撞准确、关卡可读性、即时重开和完整的 120 秒流程。不要使用或模仿现有游戏的角色、名称、音乐、Logo 或关卡素材。

04 / MEANING

这个研究的意义是什么？

A

验证“少输入也能有深度”

玩法复杂度不一定来自更多按键，也可以来自速度、时机、关卡语法和空间规则的变化。

B

研究程序化生成的公平边界

随机不是目标；真正的问题是如何在变化足够多的同时，让每次失败都能被玩家理解。

C

验证重力变化的可读性

重力门必须在玩家做出承诺前被识别，翻转后还要保留落地缓冲与连续阅读能力。

D

建立“完整优先”的原型方法

先完成通关、失败、记录和重开，再扩展视觉与内容，可以更早暴露真正的体验问题。

06 / VALUE

它的价值是什么？

游戏设计价值

一个可反复调参的单键跑酷基线

可用于研究节奏、失败归因、视觉提示与难度曲线，而不被复杂操作干扰。

工程价值

可复现的程序化生成与验证框架

固定时间步、种子化生成和浏览器测试接口，使玩法问题更容易重现和回归。

展示价值

从想法到完整产品闭环的直接证据

访问者可以立即试玩，而不需要仅凭文档或概念图理解研究结果。

复用价值

可迁移到更多小型动作游戏

输入缓冲、公平模板、风险预告、即时重开和持久化记录都能独立复用。

07 / EXTENSIONS

可扩展方向是什么？

近期 · 先验证

真人试玩与平衡数据

  • 记录失败位置、失败原因与重开率
  • 调整后 60 秒速度和障碍密度
  • 增加色弱、高对比和震动反馈选项
中期 · 扩内容

在不破坏可读性的前提下增加变化

  • 每日固定种子与短时挑战模式
  • 新的公平障碍模板和城市主题层
  • 手柄支持、PWA 安装与离线游玩
长期 · 做平台

把关卡公平性变成可研究工具

  • 关卡语法编辑器与自动可通过性检查
  • 在线排行榜和经过验证的挑战种子
  • 节奏、生成密度和失败热区可视化
扩展原则

任何新机制都不能牺牲跳跃响应、碰撞准确、危险可读性和即时重开。先证明它让核心循环更好，再决定是否保留。

08 / BOUNDARIES

当前边界与下一步

v0.1.0 已证明完整流程可成立，但尚未证明长期留存、多人群体下的平衡性或商业化可行性。当前也没有服务端排行榜、账号系统、正式音乐资产和大规模设备覆盖。

最有价值的下一步：邀请真实玩家完成 5–10 局，记录失败热区与重开行为，再据此调整难度，而不是马上增加更多机制。
