SCENE,
GENERATED.

SceneGen 把一张带物体遮罩的室内图，联合重建成多个带纹理的静态 3D 物体，并同时预测它们的相对位置、旋转与尺度，最后导出一个可编辑的 GLB 场景。

查看官方实物证据 直接看采用判断

关键区别它不是“生成一张 3D 感图片”，而是输出可旋转、可拆分查看的网格资产；但也不是已经具备物理、动画与导航的完整游戏世界。

02

HOW IT WORKS

JOINT ASSET + LAYOUT GENERATION

先理解每件物体，再让整组物体互相“看见”。

SceneGen 借用 TRELLIS 的结构化 3D latent 作为资产生成骨架，同时加入全局注意力与位置 token。这样它不需要先去资产库检索家具、再单独优化摆放，而是在同一生成流程中联合推理资产与布局。

PIPELINE EXPLORER

五步看懂一次推理

RGB＋MASK × N
STEP 01

图像与逐物体遮罩

DINOv2 提取视觉条件，VGGT 提供几何特征。多视图输入要求不同视图里的物体顺序一致；遮罩质量会直接影响后续资产边界。

OBJ AOBJ BOBJ C
STEP 02

Local Attention：修好单件物体

每个物体 token 优先关注自己的图像和遮罩特征，生成稀疏结构与外观 latent，减少相邻物体视觉内容互相污染。

ABC
STEP 03

Global Attention：让物体交换场景信息

所有物体 token 与场景条件共同交互，用“桌子靠近沙发、椅子朝向桌面”这类整体关系约束资产生成与布局。

XYZQUATS
STEP 04

Position Tokens：预测相对变换

位置头为每件物体预测 3 维平移、4 维四元数旋转和 1 维统一尺度。训练时使用 pose Huber loss，并加入 voxel collision loss 抑制穿插。

GAUSSIAN→GLB
STEP 05

网格化、UV 与纹理烘焙

解码网格与 Gaussian 外观，经过简化、补洞、xatlas UV、100 视角渲染与 1024 纹理优化后，把多件资产按预测变换组合为 GLB。

“ONE FEEDFORWARD PASS” 应该怎样理解？

它指资产和布局不再分成“检索资产 + 优化摆放”的两个独立系统；并不意味着瞬时完成。公开实现仍包含两段各 25 步的采样和较重的 GLB 纹理后处理。论文报告 A100 上一个 4 物体场景约 2 分钟。

03

CAPABILITY

WHAT IT IS / IS NOT

最接近“室内 3D 草模生成器”，还不是完整世界生成器。

判断这个库是否有用，关键不是问“效果好不好”，而是确认输出是否正好落在你的下游生产链上。

CAN DO官方实现覆盖
  • 单图 / 多视图同一室内场景的一个或多个观察视角
  • 多物体联合生成形状、纹理与相对布局共同推理
  • 独立静态网格GLB 可在 Blender / Three.js 继续处理
  • 免资产库检索不是从固定家具库挑近似模型
  • 动态物体数量推理代码可接受变化数量，但受训练分布与显存限制
NOT YET不能直接承诺
  • 无 Mask 一键生成当前仍依赖逐物体分割或框选 + SAM2
  • 精确数字孪生没有真实米制标定与可验证尺寸
  • 完整可玩关卡没有碰撞、导航、LOD、语义与交互逻辑
  • 动态角色没有骨骼、蒙皮、表情和动画
  • 任意室外世界训练与公开验证集中在室内家具场景
  • 绝对无穿插论文明确把物体碰撞列为仍待改善的问题
HARDWARE≥ 16 GB NVIDIA GPU

官方 README 的最低建议；测试环境包含 A100 与 RTX 3090，依赖 CUDA 12.1 路线。

WEIGHTSSceneGen ≈ 4.71 GB

还需要 VGGT-1B、视觉编码器与可选 SAM2 等依赖，实际环境远不止一个 checkpoint。

TRAIN RANGE最多 7 个物体

训练场景对象数上限为 7。推理超过 7 属于训练分布外使用，也会提高显存压力。

DOMAIN室内家具优先

训练数据来自 3D-FUTURE；室外、建筑壳体、人物和复杂机械不是当前强项。

HIGH FIT

室内场景 Blockout

概念图快速变成可绕看的资产与摆位草案，供 Blender 或引擎继续精修。

HIGH FIT

VR / AR 空间预演

把家居参考图转为早期空间组合，验证视角、体量和交互位置。

HIGH FIT

游戏场景预可视化

生成房间里的独立道具初稿，再补碰撞、材质、LOD 和玩法语义。

MEDIUM FIT

合成环境数据

为 embodied AI 构造可变化室内布局，但需要物理稳定性与语义标注扩展。

LOW FIT

BIM / 数字孪生

无法保证精确尺寸、构件类型、规范关系和真实不可见面。

LOW FIT

直接上线的游戏关卡

GLB 只是视觉资产集合，不包含运行时所需的完整关卡合同。

VALUE TO US

NOW / TRIGGER / FUTURE

现在的意义是建立能力接口，不是先把环境装起来。

对我们而言，SceneGen 最有价值的不是“多一个能跑的模型”，而是补上从 2D 概念资产到可编辑空间资产的中间层。是否投入应由真实下游任务触发。

NOW
当前价值 · 中低

保留研究档案与样本，不部署

现有主线偏 Canvas 2D、图像资产和工作流产品。安装 CUDA、多个 checkpoint 与重型后处理不会立刻产生回报。

05

EXTENSIONS

FROM RESEARCH OUTPUT TO PRODUCT ASSET

真正的扩展重点，是补齐 GLB 之后的生产合同。

继续堆更大的生成模型不是唯一方向。对真实产品更重要的是让结果可测量、可编辑、可运行、可追踪。

P0
RUNTIME READY

生产级 GLB 后处理

统一米制尺度、pivot 与命名；自动生成碰撞体、LOD、Meshopt / Draco、KTX2 纹理和引擎清单。

P0
PHYSICAL PRIORS

支撑、稳定与防穿插

把地面接触、承重关系、可达空间和导航约束加入训练或重排阶段，解决“看起来像房间但运行时不成立”。

P1
SEMANTIC SCENE GRAPH

物体身份与关系图

输出 object ID、类别、父子关系、支撑关系和可交互锚点，让下游不再从 Mesh 名称猜语义。

P1
CONTROL & EDITING

锁定、局部重生与尺寸控制

锁住满意物体，只重做失败对象；允许指定真实尺寸、风格、朝向和布局约束，降低整场景重采样成本。

P1
MULTI-VIEW

多视图训练与对应关系

当前多视图是推理期涌现能力。加入多视图训练、相机标定和对象对应，可以改善遮挡面与几何一致性。

P2
SERVICE & SPEED

服务化、蒸馏与缓存

用任务队列、模型常驻、分阶段缓存、减少采样步数和加速纹理烘焙，把研究脚本变为可观测服务。

P2
NEW DOMAINS

游戏、室外与可动对象

扩展数据到模块化游戏资产、建筑壳体与室外场景；更远期再叠加骨骼、关节、状态与时间一致性。

ACTIVATION RULE

WHEN TO ACT

依赖多不是问题；没有明确下游任务才是问题。

01

真实输入

已经有一张我们有权使用的室内图，并能明确标出 3–5 个目标物体。

02

真实下游

产物必须进入 Blender、Three.js、Unity 或空间产品，而不是只为了看演示。

03

计算预算

有 ≥16GB NVIDIA GPU 或可控云算力，也接受分钟级推理与额外权重。

04

清理预算

接受人工检查几何、纹理、穿插、尺度，并完成碰撞与运行时优化。

OUR DECISION 四个条件未出现：保留观察，不安装。四个条件同时出现：用一个真实场景启动 POC。
