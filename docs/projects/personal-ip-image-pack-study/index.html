PROJECT 003 · GENERATIVE ASSET GOVERNANCE

从一张头像，
到长期角色资产。

01 / 核心判断

目标：让个人形象成为可复用资产。

它把一次性生图的价值从“这一张是否好看”，迁移到“下一张能否更快、更稳、更可控”。人物不可变特征、允许变化、版本、文件规格和失败原因都被保存，新增一张资产不必从零沟通。

可信人物锚点×可控增量变体×可审计交付= 资产复利
边界：流程可以减少失控，但不能替代底层图像模型的一致性能力。

    01 / STABLE

    稳定不是“不许变化”

    六项资产都继承 v1/r1 的人物锁；表情、动作、道具和构图可以变化，脸、发型、眼镜、服装与色板不能偷偷变化。

    02 / TRACEABLE

    每张图都有来源链

    版本、anchor、唯一变量、像素尺寸、alpha、SHA-256 和 QA 结论均进入 manifest，失败原因也保留。

    03 / EXTENSIBLE

    追加 r4–r6，不重做 r1–r3

    新增讲解、庆祝和头像时只生产缺少的文件；历史资产和人物版本保持可用，这就是可持续扩展。

    04 / QA CAUGHT IT

    透明背景失败了两次

    初始变体把棋盘格画进 RGB 像素，四角 alpha 均为 255。流程拒绝“看起来透明”的假贴纸，最终改为明确带底色的全身资产。

    05 / EFFECT

    效果看四个指标

    首次通过率、人物一致性通过率、单项追加成本和渠道覆盖率，比“总共生成了多少张”更有意义。

    06 / CLAIM BOUNDARY

    证明流程，不冒充真人测试

    林简是虚构人物；本轮证明真实生产与 QA 链路，真人肖像还原仍需已授权照片另测。

      05 / 能力地图

      五层能力，一条交付链。

      越往下越接近可长期复用的产品资产。

      01

      权利门槛

      先确认肖像和风格素材权利，再允许生成。原始照片不进入默认交付包。

      PROCESS CONTROL
      02

      能力路由

      风格不仅决定外观，还明确支持、条件支持和拒绝的资产形式。

      MACHINE-READABLE SPEC
      03

      人物锚点

      用户确认原型后冻结身份锁；后续资产继承锚点，不重新设计人物。

      IDENTITY STATE
      04

      增量扩展

      每轮只改变允许字段，失败资产单独重做，避免整包重新生成。

      CONTROLLED VARIATION
      05

      可验收交付

      独立 PNG、实际尺寸、透明通道、哈希、QA 和用户验收形成记录。

      DELIVERY CONTRACT

      06 / 底层原理

      不是更长的提示词，
      而是更清楚的状态。

      1. GATE

        输入预检

        授权、照片职责、用途与资产范围先成为 brief。

      2. COMPILE

        提示词组装

        身份锁、风格规则、资产规格和唯一变量按优先级编译。

      3. FREEZE

        确认原型

        草案 dN 经用户确认后冻结为 vN 和 approved anchor。

      4. EXPAND

        单变量扩展

        表情、姿势和道具形成新的 rN，不触碰身份锁。

      5. VERIFY

        发布校验

        机器检查文件事实，人工检查人物和风格事实。

      07 / 真实边界

      四件不能被包装掉的事。

      01

      不是模型

      仓库不包含训练、LoRA、embedding 或专用人物一致性算法，最终画质依赖外部图像工具。

      02

      参考图未清权

      六组内置风格图片均为 pending_clearance，按上游规则不能送入生成模型。

      03

      视觉 QA 未自动化

      校验器检查格式、尺寸、透明像素和哈希，不能判断像不像、是否多手指或风格漂移。

      04

      缺少许可证

      研究版本根目录没有 LICENSE；本项目只引用和独立演示，不复制上游代码与素材。

      08 / 使用场景

      越需要“反复使用同一人物”，价值越高。

      采用它的判断标准不是行业，而是资产是否会持续追加、跨渠道复用和多人验收。

      KNOWLEDGE CREATOR

      知识博主 / 个人品牌

      头像、课程封面、讲解动作、社媒回复表情长期共用同一人物。

      高频追加 · 高一致性需求
      EDUCATOR

      讲师 / 顾问 / 教练

      把个人形象扩展到 PPT、课件、海报和方法论图解，减少每次重新沟通。

      多渠道 · 可审稿
      SMALL STUDIO

      小型 IP 工作室

      用角色卡、版本和 manifest 管理客户确认、返工与正式交付。

      多人协作 · 可追溯
      COMMUNITY

      社群 / 客户成功

      持续生产欢迎、答疑、提醒、庆祝等轻量表情与动作资产。

      长尾变体 · 边际成本敏感
      BRAND CHARACTER

      品牌人物 / 吉祥物

      在人物身份不变的前提下管理活动服装、节日动作和渠道尺寸。

      品牌规范 · 版本治理
      NOT THE BEST FIT

      这些情况不必上系统

      只做一张头像、追求完全写实数字人、需要连续动画或尚未解决素材权利时，直接生成或采用专门管线更合适。

      一次性 / 高写实 / 动画管线

      09 / 可扩展路线

      从 Skill，到角色资产基础设施。

      P0TRUSTED BASE

      先把“能否交付”自动化

      • 许可证、肖像授权与素材清权
      • 尺寸、alpha、哈希、OCR 和文件命名检查
      • 照片与供应商数据生命周期台账
      P1PRODUCTION ENGINE

      再把“像不像”量化

      • 多图像 provider 适配与失败重试
      • 身份、风格、肢体和道具一致性评分
      • 渠道规格编译与批量独立导出
      P2ASSET PLATFORM

      最后形成资产产品

      • 角色记忆、版本 diff、回退与分支
      • 客户确认、审批和失败资产局部重做
      • 宠物、多人、品牌角色与商业授权关系

      10 / 对我们的意义

      Project 003 补上“长期资产状态”这一层。

      Project 001 交付可运行作品；Project 002 研究如何把 Skills 组织成产品平台；Project 003 让我们看到，生成式产品还需要保存角色锚点、版本、失败记录和验收证据。它也给后续研究提供了可量化基线：单资产成本、首次通过率、一致性得分与返工率。

      真正可积累的不是某一次生成，而是下一次还能稳定继续的项目状态。
