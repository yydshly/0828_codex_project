04 / HOW IT WORKS

文件系统即数据库，
索引层决定产品能力。

PATH目录路径

表达门类与子类，例如“史藏 / 正史”。

→
NAME文件名

承担书名、注本或版本名称。

→
BODYTXT 正文

提供逐字检索与批量处理输入。

→
SNAPSHOTGit

负责分发、变更记录与版本固定。

ONLY WHEN TRIGGERED · FROM CORPUS TO PRODUCT

  1. 01来源与质量版本、底本、许可、异常
  2. 02稳定结构书、卷、篇、章、段 ID
  3. 03混合索引逐字、关键词、向量、重排
  4. 04证据组装原文、卷次、版本、链接
  5. 05评测与反馈召回、引用、无依据回答

倒排索引解决“哪些文档包含这个词”；向量召回补充语义近似；重排和引用合同决定最终结果是否可用、可解释。

05 / USE CASES

只有进入相关产品时，
它才产生直接价值。

以下场景不是当前建设计划，而是未来重新启用这份资料源的触发条件。没有明确用户、任务与验证闭环时，继续处理全库没有必要。

SEARCH

原句与出处初查

寻找人物、地名、术语、药名、典故和固定表达的出现位置。

适合：研究准备、内容考据线索
DH

数字人文分析

进行词频、共现、文本相似度、概念流变与跨门类比较。

前提：明确样本和版本偏差
NLP

古汉语模型任务

构造断句、标点、实体识别、翻译和 OCR 纠错语料。

前提：清洗、抽样复核、数据分割
EDU

教学与阅读产品

建设专题选本、课程例句、章节阅读、注释和练习系统。

前提：选择可靠文本与清楚出处
CREATIVE

文化内容创作

为历史选题、游戏世界观、文学创作与传统技艺提供素材线索。

前提：二次核对，不复制错误
PRODUCT

相关产品补充资料

当现有权威来源覆盖不足时，用它补充检索、引用、质量治理和评测样本。

适合：小范围、可验证、可替换
不应直接用于
未经核对的学术定本中医诊疗或处方决策无许可商业再分发无清洗大模型训练

07 / EXTENSION ROADMAP

当前不扩展；
被真实需求触发后再启动。

下面保留的是条件路线，不是待办清单。重新启用时仍要先比较 CText、CBETA、维基文库、机构数据库与商业数据库，确认殆知阁确实有补充价值。

P0 · TRUST

可信数据层

来源、作者朝代、版本底本、权利、hash、异常检测和质量等级。

P1 · STRUCTURE

稳定结构层

书—卷—篇—章—段稳定 ID，Markdown、TEI 或 JSONL，多版本映射。

P2 · RETRIEVAL

可验证检索层

逐字、异体归一、关键词、向量召回、重排和可复现查询。

P3 · EVIDENCE

证据型知识层

原文、卷次、版本、影印链接同行展示，回答与推断分开。

P4 · WORKSPACE

研究工作台

版本对比、批注、实体网络、时间地图、专题导出和协作校勘。

ACTIVATION RULE

有需求才启动，启动也只做 20–50 部

先证明“相关产品确实需要这批文本”，再选择来源较清楚的小样本，验证 Corpus Manifest → 结构切分 → 混合检索 → 引用型回答 → 人工核验 → 量化评测；不直接处理 4.8 GiB 全库。
