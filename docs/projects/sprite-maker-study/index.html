06

HOW IT WORKS

实现原理

让模型承担不确定创造，让代码承担可重复生产。

这条分工线比“用了哪个模型”更重要：它决定资产能否复现、修复、回退和进入游戏。

01 · ORCHESTRATE

Agent + Harness 编译需求

对话、参考图和设置被编译成角色、怪物、道具、VFX、Pack 或 Terrain 合同。路由同时使用命令、关键词和当前资产上下文。

不确定：理解、构图、源图与可选润色
↓
02 · PLAN

规则模板分配动作阶段

walk、run、attack、cast、death 等关键词进入预定义阶段；自动模式可让 Agent 看图后推荐帧数。

混合：规则骨架 + 视觉建议
↓
03 · RIG

胶囊骨骼覆盖每个非透明像素

最近骨骼兜底保证完整轮廓；最多四骨骼权重、父子仿射变换和解析式双骨 IK 生成帧。

确定性：相同输入得到相同渲染
↓
04 · VERIFY

像素指标发现结构问题

尺寸、Alpha、边缘、质心、感知哈希、调色板、帧差和循环首尾差异构成诊断报告。

边界：不能替代身份、肢体和审美判断
↓
05 · OWN

普通文件 + SQLite 保存长期状态

PNG、Sheet 和 JSON 留在项目目录；对话、版本、时间线、任务与报告进入 SQLite，并支持备份恢复。

Local-first：拥有资产，不代表云端生成完全离线

SCENARIOS

使用场景

越接近“小团队持续生产 2D 游戏资产”，匹配度越高。

它的优势来自工作流完整性，而不是单张图的绝对上限。只做一次性图片时，直接使用图像工具更简单。

HIGH FIT建议优先试用
  • 独立游戏 / Game Jam快速建立角色、怪物、道具与 VFX 基线
  • 已有角色做动作idle、walk、run、attack、death 循环
  • 协调资产包同一 art direction 下的独立 PNG 与 Manifest
  • Canvas / Phaser / Godot需要 Sheet、pivot、FPS 和 JSON
  • 长期本地资产版本、备份、非破坏修复和生成上下文
CONDITIONAL需要人工与补充工具
  • 非像素 2D可以生成，但 Rig 仍是平面像素变形
  • 严格角色一致性Rig 锁像素，重绘却可能重新漂移
  • 商业正式资产仍需版权、构图和人工艺术验收
  • Terrain 生产图集之后仍需切片、碰撞和引擎接入
  • 批量自动化桌面优先，缺少稳定 headless SDK
LOW FIT换专用方案
  • 单张头像或插画工作台成本超过任务价值
  • Spine / Live2D它主要导出烘焙 PNG 帧
  • AAA 复杂动画面部、布料和多角色表演不足
  • 3D 与移动端原生编辑不属于当前产品目标
  • 完全离线生图仓库没有附带本地模型权重
